01 · INTRODUCTION

What is Cybersecurity?

Cybersecurity is the practice of protecting computers, networks, applications and digital information against unauthorized access, misuse, damage and disruption.

Security professionals identify risks, investigate suspicious activity, secure systems and respond to incidents.

ShadowCyber teaches the foundations of these practices through structured lessons and knowledge checks.

02 · SECURITY FOUNDATIONS

Three fundamental principles guide information security.

CONFIDENTIALITY

Protect information

Ensure that only authorized people can access confidential information.

  • Access control
  • Encryption
  • Authentication
INTEGRITY

Maintain accuracy

Protect information against unauthorized modification or destruction.

04 · THREAT INTELLIGENCE

Understand Common Cyber Threats

Phishing

Fraudulent messages designed to trick people into revealing credentials or sensitive information.

Defence:

Verify senders, inspect links and use MFA.

Malware

Malicious software designed to compromise, disrupt or gain unauthorized access to systems.

Defence:

Use endpoint protection and install trusted updates.

Ransomware

Malware that encrypts or blocks access to information and demands payment.

Defence:

Maintain isolated backups and restrict permissions.

Social Engineering

Manipulation techniques used to persuade people to disclose information or perform unsafe actions.

Defence:

Verify requests and follow security procedures.

Credential Attacks

Attempts to misuse stolen, weak or reused account credentials.

Defence:

Use unique passwords, MFA and login monitoring.

Denial of Service

Attempts to make a service unavailable to legitimate users.

Defence:

Use traffic filtering, monitoring and resilience planning.

05 · WEB APPLICATION SECURITY

OWASP Security Topics

Study common web application security risks.

Important security weaknesses

  1. Broken Access Control: Users access resources beyond their permissions.
  2. Cryptographic Failures: Sensitive information lacks adequate protection.
  3. Injection: Untrusted input is interpreted as executable commands or queries.
  4. Insecure Design: Applications lack adequate security controls at the design stage.
  5. Security Misconfiguration: Incorrect settings expose systems to unnecessary risk.
  6. Authentication Failures: Weak authentication controls allow account compromise.
  7. Software Integrity Failures: Software updates or dependencies cannot be trusted.
  8. Logging and Monitoring Failures: Security incidents go undetected or lack useful records.

These are educational topic summaries. Study the current OWASP Top 10 documentation for the complete risk categories.

07 · PRACTICAL SECURITY

Essential Security Practices

  • Use unique passwords for different accounts.
  • Enable multi-factor authentication.
  • Keep operating systems and applications updated.
  • Back up important files regularly.
  • Review account permissions.
  • Encrypt sensitive information.
  • Monitor unusual account activity.
  • Verify links and attachments before opening them.
  • Use secure Wi-Fi configurations.
  • Report suspicious activity promptly.

09 · RESPONSIBLE PRACTICE

Cybersecurity Ethics

All security testing must have explicit authorization. Never test systems, networks, websites or accounts belonging to others without permission.

  • Follow the approved testing scope.
  • Do not access or modify unauthorized data.

Build your security mindset. Understand what security protects, who attacks systems, and why defenses fail.

Chapter Introduction

This chapter establishes the conceptual foundation for the entire book. You do not need any technical background, but you do need to develop a security mindset.

A security mindset means examining every system, every piece of data, and every person from a defender's perspective.

1.1 The CIA Triad

The CIA Triad is the first principle of information security. It describes three essential properties that security controls aim to protect.

Confidentiality

Data can only be accessed and read by authorized parties. Unauthorized individuals must not understand its contents.

Example

Only you know your bank card PIN. Someone who finds your card should not be able to withdraw money without it.

Protection methods
  • Encryption
  • Access control
  • Data masking

Integrity

Data remains accurate, complete, and unaltered throughout transmission, storage, and processing.

Example

You transfer $100. The bank must record $100, not $1,000 or $1.

Protection methods
  • SHA-256 hash verification
  • Digital signatures
  • Change management

Availability

Systems and data remain accessible and usable by authorized users when they need them.

Example

A hospital's medical records system must be available when a doctor needs patient information.

Protection methods
  • Redundancy and backups
  • Disaster recovery
  • DDoS protection
  • Load balancing

1.1.4 The CIA Balance

Security requires a balance between confidentiality, integrity, and availability. Excessively strict access restrictions can prevent legitimate users from accessing information. Excessively open access can expose sensitive information.

1.2 Threat Actors

Threat actors are people or groups that may attempt to compromise systems, information, or services. Their motivations and resources differ.

1.2.1 Cybercriminals

Motivation: Financial gain.

They commonly use phishing, ransomware, business email compromise, and credential theft.

1.2.2 Insiders

Insiders have legitimate access to an organization's systems or information.

  • Malicious insiders: Intentionally abuse access.
  • Negligent insiders: Create risks through careless actions.

Defenses include least privilege, access monitoring, security training, and proper employee offboarding.

1.2.3 Nation-State Actors

Motivation: Espionage, political interference, economic competition, and military objectives.

Some conduct long-term operations known as Advanced Persistent Threats (APTs).

1.2.4 Hacktivists

Motivation: Political, social, or ideological causes.

Common tactics include DDoS attacks, website defacement, and unauthorized information disclosure.

1.2.5 Script Kiddies

Individuals with limited technical knowledge who use ready-made tools developed by others.

Their motivation may include curiosity, recognition, entertainment, or showing off.

1.3 Why Security Fails

1.3.1 The Human Factor

People can be manipulated even when technical security controls are strong.

  • Authority bias: Impersonating a manager.
  • Urgency: Demanding immediate action.
  • Fear: Threatening legal or financial consequences.

1.3.2 Complexity

Modern systems contain operating systems, databases, web servers, third-party libraries, cloud services, and APIs. A weakness in one component can create an entry point into a larger system.

1.3.3 Asymmetric Warfare

Defenders must protect many systems and entry points. Attackers may only need to find one exploitable weakness.

Defense in Depth addresses this problem by using multiple layers of security controls.

1.3.4 The Good Enough Illusion

Buying a firewall or security monitoring product does not automatically make an organization secure.

Security requires continuous monitoring, detection, response, remediation, and improvement.

Chapter Summary

Confidentiality: Prevent unauthorized reading.

Integrity: Prevent unauthorized modification.

Availability: Keep systems accessible.

Threat actors: Cybercriminals, insiders, nation-state actors, hacktivists, and script kiddies.

Security failures: Human factors, complexity, asymmetric warfare, and the belief that security is a one-time purchase.
